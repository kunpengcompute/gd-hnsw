# 发行说明

## v1.0.0（首个版本）

gd-hnsw（全局分布式 HNSW 检索算法）首次发布。本版本在鲲鹏超节点 URMA 高带宽、低时延互连环境上实现分布式全局检索：在全部数据上构建一张完整 HNSW 图并分片存储，查询沿全局图跨分片搜索，只生成一份结果，避免分片独立索引方案的总计算量放大。

### 性能规格（设计目标）

验收环境：鲲鹏超节点电组网 4 节点（KP950），openEuler 24.03 LTS SP3，GCC 12.3，Milvus v3.0.0。

| 指标 | 规格 |
| --- | --- |
| 集群吞吐 | 同等算力下，对比 32 分片独立索引方案 QPS 提升 100% |
| 查询时延 | < 50 ms |
| 召回率 | > 0.95（gist、bge 数据集验收） |

### 新特性

**全局图索引**

- 在全部数据上构建完整 HNSW 图，保留跨分片边，再按全局 ID 连续分片存储；
- 查询沿同一张全局图跨分片搜索，生成一份结果，无需各分片分别 top-k 再汇聚；
- 相同召回目标下，集群总距离计算量由 `P·log(N/P)` 降至 `log N` 量级。

**URMA 数据面**

- 邻接表与向量的远端访问使用 URMA READ 单边读，通信设备直接写入本地缓冲区，远端应用线程不参与；
- 分层数据组织：上层图邻接关系每节点一份完整副本，底层邻接表与向量同分片放置；
- ShardMap 分片映射 + 定长布局直接寻址，无需先询问对端数据位置。

**距离下推（Pushdown）**

- 远端距离计算可下推至向量所在节点，只回传 ID 与距离，向量传输带宽需求降低两个数量级以上；
- 距离策略支持 `pull` / `pushdown` / `auto`，auto 按分组 ID 数量自动选择；
- 结果集合已满时下推请求携带最差距离上界，远端只回传更优候选。

**多线程运行时**

- 五类线程职责分离：Control（查询管理）、Search（搜索执行）、Distance（距离计算服务）、READ Progress（读取通信）、RPC Progress（请求与结果通信）；
- 单查询状态始终由一个 Search 线程维护，等待远端操作时可切换处理其他就绪查询，实现搜索、通信与距离服务并行重叠；
- 线程数量支持 auto 推导与显式配置（见 [最佳实践](best_practices.md)）。

**并发与资源管理**

- 查询池（`max_active_queries`）预分配固定查询位置，控制并发与内存占用；
- 查询标识携带复用代次，避免位置复用后旧通知被误认；
- 查询超时管理与完成回收由 Control 统一负责。

**索引构建与基准工具**

- `build_index`：单进程离线索引构建，支持 HDF5 与 BIN/IVEC/FBIN 数据集（自动识别）；
- 支持 k-means 聚类分片（`build.cluster`），提升数据局部性，支持按聚类中心路由查询；
- `gd_hnsw_bench`：分布式检索基准，输出 recall@k、聚合 QPS 与时延分位数；
- 预置 4 个数据集配置：bigann-128 / gist-960 / bge-1024 / openai-1536。

**Milvus 接入**

- 每个分片以 5 个角色在 URMA 资源目录发布注册内存：`topology`（图结构）、`vectors`（基向量）、`distance-tasks`、`distance-results`、`distance-notify`（距离 mailbox 三件套）；
- 基于 etcd 的服务发现：注册记录随 session 租约发布，对端经 Snapshot/Watch 拼成全局图清单并导入 peer 句柄，节点退出后租约过期自动清理；
- `shardDelegator.Search` 内 `ub.TrySearch` 分流闸门：命中配置走分布式全局检索，URMA 数据面不可用时安全回退原生检索路径，Proxy 无感知。

### 已知限制

- 部署进程（rank）数必须与索引分片数一致，每个进程加载一个分片；
- 依赖 URMA 用户态远程内存访问能力（UMDK 驱动）；无 URMA 环境仅可单机单分片运行，无跨节点通信收益；
- 索引构建为离线流程，全局索引构建成本高于分片独立索引；
- Milvus UB 链路仅支持裸向量检索计划（无标量过滤、group-by、迭代器），且要求 `0 < topk ≤ ef`；不满足条件的请求不回退，按系统错误返回；
